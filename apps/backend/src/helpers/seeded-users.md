## How to log in as any of these

- **Fastest (dev only):** open **`/dev/switch-user`** in the app and tap a user — it
  signs you in with no OTP. Backed by `GET /api/v1/dev/users` + `POST /api/v1/dev/login-as`,
  both hard-gated to `APPLICATION_ENVIRONMENT=development` (they 404 otherwise).
- **Normal flow:** request an OTP for the email on the sign-in screen.

## Admins

The admin console is now part of the **same app** as the participant surface — one
Vite deployment, one dev server (`npm run dev`, port 5173). There is **no separate
admin sign-in**: an admin signs in at the normal sign-in flow (`/`, email OTP or
Google) exactly like every other user, then the admin routes under **`/admin/*`**
become accessible. Authority is derived from each user's `administrator` /
`platformAdmin` staff-assignment (via `GET /staff-assignments/mine`):

- **Admin** (has the assignment) → `/admin/overview` and the rest of the console.
  The console is **desktop-first**: on screens narrower than 768px it shows an
  "admin works best on desktop" overlay.
- **Non-admin** who opens `/admin/*` → `/admin/not-authorized` ("This is the admin
  panel. You don't have access.") with a link back to `/discover`.
- Deep-linking `/admin/*` while signed out saves the intended route, sends you to
  sign-in, and returns you there afterwards.

## File uploads (posters)

Uploads default to **local disk** (`uploads/`, served at `/uploads/…`) in development —
no configuration needed. In production, set the three S3 credentials
(`S3_BUCKET_NAME`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`) to switch to **S3**;
uploads then return public `https://…s3….amazonaws.com/uploads/…` URLs and the
`/uploads` static mount is disabled. The active driver is logged at startup
(`Using local upload driver` / `Using S3 upload driver`). See `docs/S3_SETUP.md`.
